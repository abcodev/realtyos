# RealtyOS Demo Scenarios

회사 제출 및 면접 시연에서 사용할 대표 질문과 확인 포인트를 정리한다.

## Demo Goal

RealtyOS는 부동산 실거래 데이터를 RAG와 의사결정 엔진으로 분석하는 AI 백엔드다. 시연에서는 단순 챗봇이 아니라 실제 거래 근거를 검색하고, 질문 의도에 따라 검색/시세/비교/추천 흐름을 다르게 처리한다는 점을 보여준다.

## Scenario 1. 단지 최근 거래 검색

질문:

```text
래미안대치팰리스 최근 거래 알려줘
```

기대 흐름:

- route: `SEARCH`
- RAG 문서 검색 수행
- 근거 거래 카드 표시
- 근거가 부족하면 LLM 추측 답변을 만들지 않음

확인 포인트:

- 응답에 실제 단지명과 거래일이 포함되는지
- 엉뚱한 지역/단지가 섞이지 않는지
- source 목록이 함께 내려오는지

## Scenario 2. 지역 시세 질문

질문:

```text
개포동 시세 어때
```

기대 흐름:

- route: `MARKET_PRICE`
- 실거래 기반 decision engine 사용
- 최근가, 평균가, 중위가, 평당가, 거래건수 요약

확인 포인트:

- `개포동` 거래만 근거로 사용하는지
- 신풍동, 거제동 같은 무관 지역이 섞이지 않는지
- 근거 거래가 답변 하단에 표시되는지

## Scenario 3. 지역 비교

질문:

```text
대치동과 역삼동 시세 비교해줘
```

기대 흐름:

- route: `COMPARISON`
- 비교 대상: `대치동`, `역삼동`
- 각 지역별 후보를 분리 검색
- 비교표와 대상별 후보 목록 표시

확인 포인트:

- 한쪽 지역만 검색되지 않는지
- 비교표에 두 지역이 모두 나오는지
- 평균가/중위가/최근가/거래건수가 대상별로 분리되는지

## Scenario 4. 단지와 지역 비교

질문:

```text
잠실엘스랑 대치동 비교해줘
```

기대 흐름:

- route: `COMPARISON`
- 비교 대상: `잠실엘스`, `대치동`
- `잠실엘스`는 단지명 후보로, `대치동`은 지역 후보로 검색

확인 포인트:

- `잠실엘스`가 지역명으로만 해석되어 누락되지 않는지
- `대치동` 후보도 함께 표시되는지
- 답변이 한쪽 대상에만 치우치지 않는지

## Scenario 5. 추천/갈아타기 후보

질문:

```text
마포에서 갈아타기 후보 추천해줘
```

기대 흐름:

- route: `RECOMMENDATION`
- 단일 지역 후보 추천으로 처리
- `마포` 조건을 유지한 실거래 후보 점수화

확인 포인트:

- 부안읍, 월영동 등 무관 지역이 나오지 않는지
- 후보별 점수와 판단 포인트가 표시되는지
- 예산/면적 조건이 있을 경우 점수에 반영되는지

## Scenario 6. 조건 검색

질문:

```text
강남구 30평대 20억 이하 아파트
```

기대 흐름:

- route: 질문 표현에 따라 `SEARCH` 또는 `MARKET_PRICE`
- `강남구`, `30평대`, `20억 이하` 조건 추출
- 가격/면적 조건에 맞는 거래 근거 반환

확인 포인트:

- 전용면적 약 99㎡ ~ 132㎡ 범위가 반영되는지
- 거래금액 200,000만원 이하 조건이 반영되는지
- 강남구 외 지역이 섞이지 않는지

## Regression Checklist

시연 전 다음 질문은 반드시 확인한다.

```text
개포동 시세 어때
대치동과 역삼동 시세 비교해줘
잠실엘스랑 대치동 비교해줘
마포에서 갈아타기 후보 추천해줘
래미안대치팰리스 최근 거래 알려줘
```

실패로 봐야 하는 상태:

- 요청 지역과 무관한 지역이 상위 결과에 노출됨
- 비교 질문에서 한쪽 대상만 검색됨
- 단지명을 지역명으로만 해석해 후보를 찾지 못함
- 근거가 없는데 LLM이 확정적으로 답변함
- SSE에서 `completed` 이벤트가 내려오지 않음
